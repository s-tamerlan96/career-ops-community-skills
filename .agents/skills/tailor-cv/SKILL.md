# Tailor CV

Start by checking the role against the candidate's stated requirements. Reframe supported experience; do not invent missing experience, metrics, ownership, or authorship.

## Inputs and workspace

In a career-ops workspace, use `cv.md`, `article-digest.md`, `config/profile.yml`, `modes/_profile.md`, and user-confirmed stories in `interview-prep/story-bank.md`. `writing-samples/` and optional `voice-dna.md` may guide voice; style references do not establish career facts.

These are private user inputs, not files included in this extension pack. Use statements and documents supplied in the current conversation when the files are absent. Optional local workflow rules may guide process but must not introduce candidate claims. Never load unrelated repositories to fill career gaps.

If the current vacancy status matters, inspect the live page through the available browser workflow. If verification is unavailable, say that status is unconfirmed.

## Check fit

Compare the vacancy with the user's actual constraints:

- compensation and engagement model;
- ownership and decision rights;
- role scope and seniority;
- relevant domain experience;
- location, remote or office format, and timezone;
- material uncertainties in the role or team.

State hard mismatches before drafting. A user can choose to pursue a role despite a mismatch; preserve that choice and keep unsupported claims out of the application.

## Map evidence

Build a compact map of requirement, matching proof point, source, and gap. Distinguish transferable skills from direct domain experience. Using a tool does not establish that the candidate built it; contributing to a project does not establish sole ownership.

For AI-related claims, explain the actual function and supported outcome. Do not append an AI label to a conventional task or invent time savings.

## Choose the deliverable

Follow the user's requested mode:

- **Fit analysis:** strengths, gaps, and a recommendation tied to stated constraints.
- **Text proposal:** exact replacement text.
- **CV edit:** targeted changes to the supplied editable document.
- **ATS/PDF:** use the installed upstream PDF mode when available, otherwise an available document workflow and verify the exported result.
- **Recruiter answer:** a concise draft based on confirmed experience and the current process.

For an existing designed CV, establish the exact text changes before changing layout. Keep strong existing claims unless they are inaccurate or irrelevant to the role. A complete rewrite is appropriate when requested or clearly necessary; explain the change in emphasis.

## Design-aware edits

When the user requests edits in a design tool such as Canva, use its available editing workflow. Prefer narrow text replacements when rich-text formatting could be damaged. Preserve composition unless layout changes are requested, keep text within the available space, and inspect the final result.

If editing is unavailable or the preview cannot be verified, provide exact replacement text and state the limitation. Do not imply a saved edit or exported PDF exists when it does not.

## Final check

Verify that:

- every career claim has an allowed source;
- achievements, contribution, and ownership are distinguished;
- transferable experience is not presented as direct experience;
- key mismatches remain visible;
- the final file is readable, and the requested output format works;
- no confidential detail was added to an externally intended document.

Report the changes and unresolved gaps. Drafting or editing does not authorize sending the CV, submitting an application, or contacting someone.

# Career Ops Community Skills

Обезличенный набор из девяти дополнительных скиллов и правил для [career-ops](https://github.com/career-ops-hq/career-ops). Помогает вести карьерные кейсы, готовиться к интервью, разбирать обратную связь, фиксировать профессиональный рост и улучшать правила агента через **Error Review (`error-review`)**.

Это отдельный пакет расширений. Для сканирования вакансий, оценки предложений, трекера и генерации CV нужна базовая установка career-ops. Личные резюме, переписки, вакансии, зарплатные условия и история рабочего репозитория в этот пакет не включены.

## Первоисточник и вклад

Оригинальный **career-ops** создан **Santiago Fernández de Valderrama ([santifer](https://santifer.io))** и распространяется по MIT. Исходная ссылка [santifer/career-ops](https://github.com/santifer/career-ops) сейчас ведёт на [career-ops-hq/career-ops](https://github.com/career-ops-hq/career-ops). Авторство базовой системы, её режимов, скоринга, сканера, трекера, шаблонов и механизма разделения пользовательских и системных данных принадлежит первоисточнику и его участникам.

Этот community-пакет вырос из локальной адаптации career-ops. Здесь опубликованы обезличенные дополнения: девять специализированных скиллов, правила работы с доказательствами и ошибками, шаблоны передачи кейса, проверка готовности кейсов, безопасный установщик и проверки состава публикации. Это независимое расширение; оно не является официальным релизом upstream и не переносит результаты чужого поиска работы на нового пользователя. Подробнее: [ORIGIN.md](ORIGIN.md), [LICENSE](LICENSE).

## Error Review: разбор ошибок агента

[error-review](.agents/skills/error-review/SKILL.md) работает с ошибками, которые пользователь описал в текущем разговоре или записал в своём `memory/errors.md`. Он отделяет подтверждённую ошибку от ограничения инструмента, предпочтения пользователя и предположения о причине, затем предлагает конкретную правку рабочего правила.

После согласования скилл обновляет соответствующие правила, переносит разобранные записи в `memory/errors_archive.md` и сохраняет нерешённые вопросы в журнале. Если ошибок нет, он не придумывает их для заполнения отчёта. В пакет входят пустые шаблоны журналов; история ошибок другого пользователя не переносится.

## Правила и процессная память

Правила дополнительно закрепляют:

- Разделение подтверждённых фактов, решений пользователя, интерпретаций и пробелов.
- Запрет на придуманные достижения, метрики и авторство; память агента не служит источником карьерных фактов.
- Различие между решением работодателя, конкретной обратной связью и вежливым тоном.
- Сохранение контекста и закрытие подтверждённо завершённых кейсов.
- Разделение личных материалов, рабочих правил и конфиденциальных данных работодателя.
- Проверку итогового текста и разрешения перед отправкой сообщений и заявок.

Правила находятся в [rules/AGENTS.fragment.md](rules/AGENTS.fragment.md), а начальные шаблоны процессной памяти — в [rules/memory](rules/memory).

Установщик создаёт в пользовательском проекте только отсутствующие файлы:

| Файл | Назначение |
|---|---|
| [memory/rules.md](rules/memory/rules.md) | Работа с фактами, границами ответственности, кейсами и обратной связью |
| [memory/quality_bar.md](rules/memory/quality_bar.md) | Проверки качества CV, подготовки, разбора интервью и передачи кейса |
| [memory/source_map.md](rules/memory/source_map.md) | Какие источники допустимы для карьерных утверждений и что нельзя брать из памяти агента |
| [memory/permissions.md](rules/memory/permissions.md) | Разрешения на отправку, публикацию и изменение постоянных правил |
| [memory/cv_flow.md](rules/memory/cv_flow.md) | Порядок адаптации CV и проверки текста и макета |
| [memory/errors.md](rules/memory/errors.md) | Пустой журнал для будущих подтверждённых ошибок агента |
| [memory/errors_archive.md](rules/memory/errors_archive.md) | Пустой архив для записей, разобранных через Error Review |

Вместе со скиллами поставляются шаблоны передачи кейса — [case.json](.agents/skills/career-case-handoff/assets/case.template.json), [HANDOFF.md](.agents/skills/career-case-handoff/assets/HANDOFF.template.md) и [INDEX.md](.agents/skills/career-case-handoff/assets/INDEX.template.md), — а также [банк вопросов для продуктовых интервью](.agents/skills/pm-interview-coach/references/question-bank.md), [критерии оценки](.agents/skills/pm-interview-coach/references/rubric.md) и [методика проверки зарплатных источников](.agents/skills/compensation-research-flow/references/russian-source-audit.md).

После сохранения первого кейса через `career-case-handoff` можно отдельно запустить [аудитор готовности](.agents/skills/career-case-handoff/scripts/audit-handoffs.mjs) **из каталога своего рабочего career-ops**:

```bash
node .agents/skills/career-case-handoff/scripts/audit-handoffs.mjs
```

Он проверяет структуру кейса, обязательные файлы, даты и отмеченные зависимости. Достоверность самих карьерных фактов требует проверки источников.

## Установка

Нужны Git, Node.js 22+ и локальная установка career-ops. Сам пакет не требует npm-зависимостей, API-ключей или отдельного сервера. Средства поиска, браузер и интеграции для конкретного скилла предоставляет ваш агент; при их отсутствии он должен обозначить пробел.

```bash
# Если базовой установки ещё нет:
git clone https://github.com/career-ops-hq/career-ops.git

# Рядом с ней:
git clone https://github.com/s-tamerlan96/career-ops-community-skills.git
cd career-ops-community-skills

# Сначала только показать изменения:
node scripts/install.mjs ../career-ops

# Установить после просмотра:
node scripts/install.mjs ../career-ops --apply
```

Затем завершите обычную настройку базового career-ops по его README и откройте каталог `career-ops` в вашем агенте. Скиллы располагаются в `.agents/skills/`. В Codex их можно вызвать по имени; в другом агенте, если автоматическое обнаружение не поддерживается, попросите прочитать соответствующий `SKILL.md` и выполнить его инструкции.

Установщик копирует скиллы, добавляет отмеченный блок в `AGENTS.md` и создаёт только отсутствующие файлы процессной памяти. Существующую память и пользовательские материалы он сохраняет. Если файл уже установленного скилла отличается, установка остановится до записи: сначала сравните версии вручную. Повторная установка одинаковой версии не меняет файлы.

В `.gitignore` добавляется блок для личных материалов. Он не удаляет уже отслеживаемые файлы или старые коммиты: личный рабочий репозиторий должен оставаться приватным. Обновления upstream могут заменить `AGENTS.md`; после обновления проверьте наличие блока расширения и при необходимости повторите установку.

Скиллы подготовлены по локальной базе career-ops **v1.16.0**. Установщик проверяет структуру проекта; совместимость со всеми последующими версиями и всеми агентами не заявляется.

## MCP и коннекторы: опыт и необязательные примеры

MCP позволяет агенту обращаться к инструментам и источникам данных. В некоторых клиентах такое подключение предлагается как готовый коннектор или приложение. **Пакет не устанавливает MCP-серверы и не требует подключения перечисленных сервисов.** Названия ниже показывают возможную роль интеграции в процессе; это примеры, а не реклама или обязательный набор.

### Что использовалось в исходном процессе

| Интеграция | Для чего использовалась | Альтернатива без этого сервиса |
|---|---|---|
| **Granola через подключённые инструменты агента** — [официальная документация MCP](https://docs.granola.ai/help-center/sharing/integrations/mcp) | Обращение к заметкам интервью для `interview-feedback-loop`. При наличии полного транскрипта предпочтителен он; краткие заметки нельзя выдавать за дословную запись. Сам вызов коннектора не гарантирует доступ к нужной встрече | Передать локальный транскрипт, текст заметок или собственный пересказ; агент должен явно указать тип источника |
| **Canva через подключённые инструменты агента** — [официальная документация MCP](https://www.canva.dev/docs/mcp/) | Просмотр и точечное редактирование CV в `tailor-cv`, с проверкой текста и макета. При недостаточном контроле верстки использовался локальный HTML/CSS → PDF | Редактируемый локальный документ, HTML/PDF или список точных текстовых замен |

Это описание использования интеграций в рабочем процессе, а не заявление о тестировании каждой текущей версии официального MCP-сервера. Ссылки ведут на актуальные инструкции поставщиков; конкретный набор инструментов зависит от клиента и прав доступа.

При подготовке публикации также использовался GitHub-коннектор для проверки подключённой учётной записи. Загрузка репозитория и создание релиза выполнялись через **Git и GitHub CLI (`gh`)**. Эти операции не требуют GitHub MCP.

### Что можно подключить под конкретную задачу

| Потребность | Необязательный пример | Когда полезен и чем заменить |
|---|---|---|
| Читать живую страницу вакансии и проверять её состояние | [Playwright MCP](https://github.com/microsoft/playwright/blob/main/docs/src/getting-started-mcp.md) | Для браузерной проверки вакансий в `interview-prep-flow` и `tailor-cv`. Можно использовать браузерный инструмент своего агента или проверить страницу вручную. Один сохранённый текст вакансии не подтверждает её текущую активность |
| Работать с карьерными заметками, уже хранящимися в облаке | [Notion MCP](https://developers.notion.com/guides/mcp/overview) | Если пользователь сам выбрал Notion для своих документов. Альтернатива — Markdown в локальном career-ops или экспорт нужного документа. Подключение не означает автоматическую синхронизацию всех кейсов |
| Читать репозиторий, изменения и задачи проекта через агента | [GitHub MCP Server](https://github.com/github/github-mcp-server) | Для сопровождения пакета и разрешённой работы с репозиториями. Альтернатива — Git, `gh` или веб-интерфейс. Для подготовки к интервью и ведения локального журнала ошибок не нужен |

Эти дополнительные MCP приведены как варианты для соответствующих задач; они не заявлены как протестированный вместе с пакетом набор. Начните с локальных файлов и подключайте сервис, когда он нужен для выбранного источника или действия. Для `error-review`, тренировок интервью и локальных кейсов обычно достаточно самого агента и файлов проекта.

При подключении проверьте официальную инструкцию, доступные инструменты, разрешения и доступность нужной функции в своём аккаунте. Для чтения источников достаточно доступа на чтение; запись, отправка и публикация следуют разрешениям пользователя. Токены, параметры личных подключений, ссылки на частные документы и содержимое встреч не входят в этот публичный пакет. Официальные страницы выше проверены 2026-09-17; текущие условия следует смотреть у поставщиков.

## Примеры запросов

> Используй career-case-handoff: сохрани текущий кейс и проверь, что его можно продолжить в новом чате.

> Используй career-growth-loop: помоги зафиксировать известные ожидания после выхода на работу и вопросы для руководителя.

> Используй compensation-research-flow: сравни источники вознаграждения для этой роли; раздели gross/net, фиксированную часть и бонусы, обозначь пробелы.

> Используй interview-prep-flow: подготовь меня к продуктовому интервью по этой вакансии. Не добавляй опыт, которого нет в моём CV.

> Используй mock-interview-loop: задавай по одному вопросу, дождись ответа, затем дай разбор.

> Используй pm-interview-coach: выбери продуктовый кейс для этапа hiring manager и оцени мой ответ по подходящим критериям.

> Используй interview-feedback-loop: разбери эту запись состоявшегося интервью, отдели мои реальные ответы от предложенных улучшений.

> Используй tailor-cv: предложи изменения моего CV под эту вакансию, сохрани подтверждённые факты и границы моей ответственности.

> Используй error-review: разбери накопленные ошибки и предложи изменения правил на согласование.

## Проверки и приватность

```bash
npm test
```

Проверяются разрешённый состав пакета, SHA-256 файлов, типичные признаки секретов и персональных контактов, структура скиллов, работа установщика и аудит кейсов на искусственных примерах. Проверки запускаются локально; GitHub Actions в этот релиз не включён. Источники и границы проверки описаны в [PRIVACY.md](PRIVACY.md), результаты релизной проверки — в [VALIDATION.md](VALIDATION.md).

Публикация не содержит личного рабочего состояния. В ней сохранены атрибуция первоисточника, адрес этого публичного репозитория, сведения о релизе и названия общедоступных инструментов и источников как примеры. GitHub показывает аккаунт владельца репозитория: обезличивание содержимого не скрывает аккаунт публикации.

При изменении пакета сначала проверьте каждый изменённый файл. Для новых файлов после проверки добавьте точные пути в `scripts/package-policy.mjs`. Затем обновите контрольные суммы командой `node scripts/update-manifest.mjs` и снова выполните `npm test`. Автоматический поиск не заменяет ручную проверку контекста; обновление манифеста само по себе не означает, что новый файл безопасен.

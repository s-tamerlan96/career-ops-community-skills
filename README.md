# Career Ops Community Skills

Обезличенный набор из девяти дополнительных скиллов и правил для [career-ops](https://github.com/career-ops-hq/career-ops). Помогает вести карьерные кейсы, готовиться к интервью, разбирать обратную связь и фиксировать профессиональный рост с опорой на подтверждённые факты.

Это отдельный пакет расширений. Для сканирования вакансий, оценки предложений, трекера и генерации CV нужна базовая установка career-ops. Личные резюме, переписки, вакансии, зарплатные условия и история рабочего репозитория в этот пакет не включены.

## Первоисточник и вклад

Оригинальный **career-ops** создан **Santiago Fernández de Valderrama ([santifer](https://santifer.io))** и распространяется по MIT. Исходная ссылка [santifer/career-ops](https://github.com/santifer/career-ops) сейчас ведёт на [career-ops-hq/career-ops](https://github.com/career-ops-hq/career-ops). Авторство базовой системы, её режимов, скоринга, сканера, трекера, шаблонов и механизма разделения пользовательских и системных данных принадлежит первоисточнику и его участникам.

Этот community-пакет вырос из локальной адаптации career-ops. Здесь опубликованы обезличенные дополнения: девять специализированных скиллов, правила работы с доказательствами и ошибками, шаблоны передачи кейса, проверка готовности кейсов, безопасный установщик и проверки состава публикации. Это независимое расширение; оно не является официальным релизом upstream и не переносит результаты чужого поиска работы на нового пользователя. Подробнее: [ORIGIN.md](ORIGIN.md), [LICENSE](LICENSE).

## Что добавлено

| Скилл | Для чего нужен |
|---|---|
| [career-case-handoff](.agents/skills/career-case-handoff/SKILL.md) | Сохранить состояние кейса и продолжить его в другом чате; проверить файлы, пробелы и следующий шаг |
| [career-growth-loop](.agents/skills/career-growth-loop/SKILL.md) | Вести карьерный кейс после найма: ожидания руководителя, результаты, обратную связь и развитие |
| [compensation-research-flow](.agents/skills/compensation-research-flow/SKILL.md) | Сравнивать источники вознаграждения, разделять gross/net, фиксированную часть и бонусы |
| [interview-prep-flow](.agents/skills/interview-prep-flow/SKILL.md) | Готовиться к конкретному этапу интервью на основе вакансии и реального опыта |
| [mock-interview-loop](.agents/skills/mock-interview-loop/SKILL.md) | Проводить пробное интервью по одному вопросу и улучшать ответ после обратной связи |
| [pm-interview-coach](.agents/skills/pm-interview-coach/SKILL.md) | Тренировать продуктовые интервью с банком вопросов и критериями оценки |
| [interview-feedback-loop](.agents/skills/interview-feedback-loop/SKILL.md) | Разбирать состоявшееся интервью, учитывая говорящих, формулировки и тайминг в пределах доступного источника |
| [tailor-cv](.agents/skills/tailor-cv/SKILL.md) | Адаптировать CV под вакансию, сохраняя факты, границы ответственности и нужный формат |
| [error-review](.agents/skills/error-review/SKILL.md) | Превращать подтверждённые ошибки агента в согласованные рабочие правила |

Правила дополнительно закрепляют:

- Разделение подтверждённых фактов, решений пользователя, интерпретаций и пробелов.
- Запрет на придуманные достижения, метрики и авторство; память агента не служит источником карьерных фактов.
- Различие между решением работодателя, конкретной обратной связью и вежливым тоном.
- Сохранение контекста и закрытие подтверждённо завершённых кейсов.
- Разделение личных материалов, рабочих правил и конфиденциальных данных работодателя.
- Проверку итогового текста и разрешения перед отправкой сообщений и заявок.

Правила находятся в [rules/AGENTS.fragment.md](rules/AGENTS.fragment.md), а начальные шаблоны процессной памяти — в [rules/memory](rules/memory).

## Установка

Нужны Git, Node.js 22+ и локальная установка career-ops. Сам пакет не требует npm-зависимостей, API-ключей или отдельного сервера. Средства поиска, браузер и интеграции для конкретного скилла предоставляет ваш агент; при их отсутствии он должен обозначить пробел.

```bash
# Если базовой установки ещё нет:
git clone https://github.com/career-ops-hq/career-ops.git

# Рядом с ней:
git clone https://github.com/s-tamerlan96/career-ops-community-skills.git
cd career-ops-community-skills

# Сначала только показать изменения:
node scripts/install.mjs ../career-ops

# Установить после просмотра:
node scripts/install.mjs ../career-ops --apply
```

Затем завершите обычную настройку базового career-ops по его README и откройте каталог `career-ops` в вашем агенте. Скиллы располагаются в `.agents/skills/`. В Codex их можно вызвать по имени; в другом агенте, если автоматическое обнаружение не поддерживается, попросите прочитать соответствующий `SKILL.md` и выполнить его инструкции.

Установщик копирует скиллы, добавляет отмеченный блок в `AGENTS.md` и создаёт только отсутствующие файлы процессной памяти. Существующую память и пользовательские материалы он сохраняет. Если файл уже установленного скилла отличается, установка остановится до записи: сначала сравните версии вручную. Повторная установка одинаковой версии не меняет файлы.

В `.gitignore` добавляется блок для личных материалов. Он не удаляет уже отслеживаемые файлы или старые коммиты: личный рабочий репозиторий должен оставаться приватным. Обновления upstream могут заменить `AGENTS.md`; после обновления проверьте наличие блока расширения и при необходимости повторите установку.

Скиллы подготовлены по локальной базе career-ops **v1.16.0**. Установщик проверяет структуру проекта; совместимость со всеми последующими версиями и всеми агентами не заявляется.

## Примеры запросов

> Используй career-case-handoff: сохрани текущий кейс и проверь, что его можно продолжить в новом чате.

> Используй interview-prep-flow: подготовь меня к продуктовому интервью по этой вакансии. Не добавляй опыт, которого нет в моём CV.

> Используй mock-interview-loop: задавай по одному вопросу, дождись ответа, затем дай разбор.

> Используй career-growth-loop: помоги зафиксировать известные ожидания после выхода на работу и вопросы для руководителя.

> Используй error-review: разбери накопленные ошибки и предложи изменения правил на согласование.

## Проверки и приватность

```bash
npm test
```

Проверяются разрешённый состав пакета, SHA-256 файлов, типичные признаки секретов и персональных контактов, структура скиллов, работа установщика и аудит кейсов на искусственных примерах. Проверки запускаются локально; GitHub Actions в этот релиз не включён. Источники и границы проверки описаны в [PRIVACY.md](PRIVACY.md), результаты релизной проверки — в [VALIDATION.md](VALIDATION.md).

Публикация не содержит личного рабочего состояния. Открыты только необходимые сведения об авторе первоисточника, адрес этого публичного репозитория и сведения о релизе. GitHub показывает аккаунт владельца репозитория: обезличивание содержимого не скрывает аккаунт публикации.

При изменении пакета сначала проверьте каждый изменённый файл. Для новых файлов после проверки добавьте точные пути в `scripts/package-policy.mjs`. Затем обновите контрольные суммы командой `node scripts/update-manifest.mjs` и снова выполните `npm test`. Автоматический поиск не заменяет ручную проверку контекста; обновление манифеста само по себе не означает, что новый файл безопасен.
